心法：你不是在学新语言，是在学新方言

TS 和 Java 都是静态类型的 C 系语言。先建立全局映射，再逐个击破：

变量与基本类型

int age = 25;                 // 整数（约 ±21 亿）
long id = 1L;                 // 长整数，字面量带 L；数据库主键用它
double price = 9.9;           // 小数
boolean active = true;        // 注意不是 boolean 小写问题：就是 boolean
String name = "周志明";        // 字符串，首字母大写，是对象

final String city = "杭州";   // final ≈ TS 的 const，赋值后不可变
var count = 10;               // Java 10+ 的局部类型推断，≈ TS 自动推断
第一个坑：整数除法 5 / 2 在 TS 里是 2.5，在 Java 里是 2——两个 int 相除结果还是 int，直接截断。要小数就先把一边变成 double：5.0 / 2。数据库里存金额永远不用 double（用 BigDecimal），这会是面试考点。

String：头号坑在这里

Java 里比较字符串内容必须用 equals，不能用 ==。== 比较的是引用（是不是同一个对象），不是内容：

String a = "hello";
String b = new String("hello");

a == b          // false！引用不同
a.equals(b)     // true ✓ 内容相同

为什么 TS 没有这个问题？因为 JS 字符串是原始值，=== 就比内容。Java 的 String 是对象，所以有了这个坑。日常记死一条：比字符串内容，永远写 equals。

类与方法：并排看一眼

TypeScript
class Book {
  private title: string;

  constructor(title: string) {
    this.title = title;
  }

  getTitle(): string {
    return this.title;
  }
}
Java
public class Book {
    private String title;

    public Book(String title) {
        this.title = title;
    }

    public String getTitle() {
        return this.title;
    }
}

结构几乎一样，只多了四个高频修饰符：

修饰符含义速记
public谁都能访问≈ TS 的 export 语义
private只有本类能访问和 TS private 意思相同，但 Java 是真·访问控制
void方法不返回值≈ 返回类型标注为 void
static属于类而非实例和 TS/JS 的 static 相同

还有一个 TS 没有的概念：方法重载（overload）——同名方法可以有多个，靠参数列表区分。看到同名不同参的两个方法，不是重复代码，是重载。

POJO + Lombok：公司代码里 90% 的类长这样

Java 没有 TS 那种「对象字面量直接当数据用」的写法——数据必须装进类里。这种纯数据类叫 POJO，正规写法要给每个字段手写 getter/setter：

public class Book {
    private Long id;
    private String title;
    private String author;
    private Integer status;

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    // ... id、author、status 还各要一对，共 8 个方法
}

没人真手写这些。Lombok 一个注解全搞定——这就是你在公司代码里见到的样子：

@Data                          // 编译期自动生成全部 getter/setter/toString/equals
public class Book {
    private Long id;
    private String title;
    private String author;
    private Integer status;
}
Lombok 三件套（公司代码必见） ① @Data：数据类的全部样板代码；② @Slf4j：给类注入一个 log 对象，直接 log.info("xxx") 打日志；③ @RequiredArgsConstructor：给所有 final 字段生成构造器——配合 Spring 的依赖注入（0001 见过的 @Autowired 的现代替代写法）。

接口：名义类型，这是最大的心智差异

TS 的 interface 是结构化类型——长得像就行。Java 的 interface 是名义类型——必须显式声明 implements，Java 不认「鸭子类型」：

public interface BookService {
    Book getById(Long id);
}

// 必须写 implements，写了才有关系，长得像没用
@Service
public class BookServiceImpl implements BookService {
    @Override
    public Book getById(Long id) { return bookMapper.selectById(id); }
}

所以公司项目里 XxxService 接口 + XxxServiceImpl 实现类成对出现是标准操作。另外注意 0001 的 Mapper：interface BookMapper extends BaseMapper<Book>——接口继承接口用 extends，类实现接口用 implements。@Override 注解表示「我正在实现/覆盖父类方法」，写错方法名它会报错帮你兜底。

你想要的JS 写法Java 写法
有序列表const books: Book[]List<Book> books = new ArrayList<>();

API 对照（左边 Java，右边 JS）：

操作Java ListJS Array
加一个list.add(book)arr.push(book)
取第 i 个list.get(0)arr[0]

注意 Java 的 Map.get("不存在的key") 返回 null 而不是 undefined——判空逻辑接下来在异常/null 一节说。

泛型：你已经会了 90%

List<Book> 的尖括号和 Array<Book> 一模一样，编译期检查类型。唯一日常注意点：尖括号里只能装对象类型，不能装原始类型——List<int> 不合法，要写 List<Integer>（Integer 是 int 的包装类，数据库查出来的 id 是 Long 也是同理）。Integer/Long 可以为 null，所以「数据库字段是 NULL」在 Java 里就是「包装类对象是 null」。

异常：TS 没有的概念 —— checked 异常

语法上 try/catch/finally 和 JS 几乎一样，但 Java 有一个 JS 完全没有的划分：

类别代表规则
unchecked（RuntimeException 及其子类）NullPointerException、IllegalArgumentException不用声明，随便抛——TS 心智模型
checked（其它 Exception）IOException、SQLException编译器强制：要么 try-catch，要么方法签名声明 throws
// checked 异常的两种合法处理，二选一，不写编译不过：
public Book read(Long id) throws IOException { ... }   // ① 声明「我不处理，往上抛」

public Book read2(Long id) {                            // ② 现场处理
    try {
        ...
    } catch (IOException e) {
        log.error("读文件失败", e);
        throw new RuntimeException(e);                  // 包装成 unchecked 继续抛也常见
    }
}
为什么公司代码里很少看到 try/catch 不是没有异常，是被统一处理了：Service 层直接 throw new RuntimeException("库存不足")，一个全局异常处理器（@RestControllerAdvice）统一接住、包装成统一 JSON 返回。读懂这个套路，你就懂了 80% 的公司异常风格。

注解：长得像装饰器，机制完全不同

TS 装饰器是函数，会改行为；Java 注解只是贴在代码上的标签，本身什么都不做——是 Spring 这类框架在启动时扫描标签、再决定装配什么。所以别问「这个注解是怎么实现的」，先问「哪个框架在读它」。

你会在公司代码看到的人话
@Override编译器检查：这确实是在覆盖父类方法
@Data / @Slf4jLombok：生成样板代码（编译期处理，唯一「做事」的注解）
@RestController / @ServiceSpring：把这个类注册进容器
@GetMapping / @PostMappingSpring：把 URL 绑定到方法
@Autowired / @ResourceSpring：把依赖塞进来（或配合 @RequiredArgsConstructor 走构造器注入）
@TableName("book")MyBatis-Plus：这个类对应哪张表

能读懂级：lambda、Stream、Optional

不强求会写，但公司代码里一定会遇到，目标是看到不慌：

lambda ≈ 箭头函数

JS
const f = (a, b) => a + b;
book => book.title
Java
// -> 代替 =>
Function f = a -> a * 2;
book -> book.getTitle()

Stream ≈ filter/map/reduce 链

// JS:  books.filter(b => b.status === 1).map(b => b.title)
List<String> names = books.stream()
        .filter(b -> b.getStatus() == 1)
        .map(Book::getTitle)            // Book::getTitle ≈ b => b.getTitle()（方法引用）
        .collect(Collectors.toList());  // 结尾要收一次，这是 JS 没有的仪式感

Optional ≈ null 安全链

// TS:  user?.nickname ?? "匿名"
String nickname = Optional.ofNullable(user)
        .map(User::getNickname)
        .orElse("匿名");
读懂优先 这三样是「看得懂、必要时能照猫画虎」即可。会在实战里反复见到，自然会写，不用提前背。

实战阅读：把第 1 课的地图代码化

现在你已经能逐行读懂它了——这就是公司项目一个典型接口的完整样子：

@RestController                          // 0001 讲过：路由模块
@RequestMapping("/api/books")            // 这个类下所有接口的 URL 前缀
@RequiredArgsConstructor                 // Lombok：给 final 字段生成构造器 → 构造器注入
public class BookController {

    private final BookService bookService;   // final + 构造器注入 ≈ @Autowired，但更推荐

    @GetMapping("/{id}")                     // GET /api/books/1 走这个方法
    public Book getById(@PathVariable Long id) {   // @PathVariable：URL 里的 {id} 填进参数
        return bookService.getById(id);      // 委托给业务层
    }
}

@Service
@RequiredArgsConstructor
public class BookServiceImpl implements BookService {

    private final BookMapper bookMapper;     // 0001 讲过：BaseMapper 白送 CRUD

    @Override
    public Book getById(Long id) {
        Book book = bookMapper.selectById(id);       // 生成 SQL 查库
        if (book == null) {                          // 没查到 → 抛业务异常，全局处理器接住
            throw new RuntimeException("图书不存在: " + id);
        }
        return book;
    }
}

逐行问自己：每个注解什么意思？private final 为什么？哪里在抛 unchecked 异常？都答得上来，这课的目标就达成了。

练习场

练习 1 · 判断两个字符串变量内容是否相同，正确写法是？

解析：== 比较引用是否同一个对象，不比内容。Java 字符串是对象，比内容永远用 equals。=== 在 Java 里根本不存在。

练习 2 · Java 里 System.out.println(5 / 2) 输出什么？

解析：两个 int 相除，结果还是 int，小数部分直接截断（不是四舍五入）。要 2.5 得写 5.0 / 2。这是前端转 Java 最容易摔的第一个算术坑。

练习 3 · 方法抛出 IOException（checked 异常）时，编译器要求什么？

解析：checked 异常是编译器强制的契约。RuntimeException（unchecked）则完全不用声明——公司代码里 throw new RuntimeException 满天飞就是这个原因。

练习 4 · 这段 Stream 等价于哪行 JS？
books.stream().filter(b -> b.status == 1).map(Book::getTitle).collect(toList())

解析：先 filter 后 map，顺序和 JS 一致；Book::getTitle 是方法引用，等价于 b => b.getTitle()。唯一多的仪式感是结尾 collect 收集。

凭回忆作答（不看上文）

检索练习是记忆真正的来源——先在心里答完，再点开核对。

Q1：Lombok 三件套是哪三个注解，各自干什么？

@Data 生成 getter/setter/toString/equals；@Slf4j 注入 log 对象打日志；@RequiredArgsConstructor 给 final 字段生成构造器（配合 Spring 构造器注入）。

Q2：TS 的 interface 和 Java 的 interface 最大差异是什么？

TS 是结构化类型（长得像就行）；Java 是名义类型，必须显式 implements 才有关系。所以公司项目里 Service 接口 + ServiceImpl 实现类成对出现。

Q3：公司代码很少写 try/catch，异常去哪了？

Service 层直接抛 RuntimeException，由全局异常处理器（@RestControllerAdvice）统一接住、包装成统一 JSON 返回给前端。
