你熟悉的Spring Boot 里对应

项目结构：一张地图

公司这种 Spring Boot 单体项目，代码几乎都长这一个模样：

src/main/java/com/company/project/
├── controller/      ← 入口层：接收 HTTP 请求，返回 JSON
│   └── UserController.java
├── service/         ← 业务层：干活的核心逻辑在这里
│   └── UserService.java
├── mapper/          ← 数据层：MyBatis-Plus 负责读写数据库
│   └── UserMapper.java
└── entity/          ← 数据表结构：一个类对应一张表
    └── User.java
记忆口诀 请求从 controller（接待）进，交给 service（干活），需要数据就找 mapper（取货），货物的形状由 entity（图纸）定义。

注解四件套：每个文件顶上那几个 @

Java 没有你熟悉的 export / 路由注册，取而代之的是注解——贴在类或方法上的标签，Spring 启动时扫描它们并自动装配：

注解作用前端人话
@RestController宣告：这个类负责 HTTP 接口“我是一个路由模块”
@GetMapping("/api/users/{id}")把 URL + GET 方法绑定到下面的函数“GET 这个路径走我这个 handler”
@Service宣告：这是业务逻辑类，注册进容器“我是可复用的业务模块”
@AutowiredSpring 自动把依赖塞进来，不用手动 new“别自己 new，容器给你注入”（类似全局的依赖注入）

MyBatis-Plus：Mapper 为什么这么薄

Mapper 接口里通常一行方法都不用写——继承 BaseMapper<User> 就白拿全套 CRUD：

@Mapper
public interface UserMapper extends BaseMapper<User> {
    // selectById / selectList / insert / updateById / deleteById 全部免费
}

Mapper 把方法翻译成 SQL：selectById(1) → SELECT * FROM user WHERE id = 1。这就是“中小公司 Java 项目”的标配打法，也是你面试八股的主战场之一。

练习 2 · 需求来了：「新增一个根据邮箱查用户的接口」，代码主要要动哪三层？

解析：入口要加路由方法（Controller）、查询逻辑要写（Service）、数据查询要实现（Mapper）。Entity 只有表结构变了才动，前端接口是你最擅长的部分。

练习 3 · @Autowired 做的事，最准确的描述是？

解析：@Autowired = 依赖注入。你不用 new UserService()，Spring 容器启动时已经把所有带 @Service 的类实例化好，谁需要就自动塞给谁。这是 Spring 最核心的思想（IoC），阶段 2 会深挖。

凭回忆作答（不看上文）

检索练习是记忆真正的来源——先在心里答完，再点开核对。

Q1：一个请求依次流经哪三层？每层的职责是什么？

Controller 接住请求、解析参数 → Service 执行业务逻辑 → Mapper 读写数据库。数据原路返回，Spring 自动序列化成 JSON。

Q2：接一个新接口需求，代码应该往哪些目录里放？

controller/ 加路由方法，service/ 加业务方法，mapper/ 视情况加查询方法（BaseMapper 白送的可能就够用了）。

Q3：MyBatis-Plus 的 BaseMapper 免费送你哪些常用方法？

selectById、selectList、insert、updateById、deleteById 等全套单表 CRUD，不用写 SQL。
